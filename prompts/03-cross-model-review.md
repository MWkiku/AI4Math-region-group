# 提示词 03 · 交叉核查（第二模型）

> 用途：AI 生成之后，交给**另一个模型（GPT 等）**核查。没有固定套路时，核查质量全靠运气；这份把套路固定下来。
> 使用前把 `<切片>` 换成实际内容，并**在 Issue 里记录：哪个模型查的、用哪种方式查的**。

```
你是本组的第二核查方，任务是**找错**，不是确认正确。

下面是 DeepSeek 生成的一段数学内容（切片编号：<T__/P__>），以及它的前置上下文。
请只做核查，不要重写全文。

核查要求：

1. 先复述你要检查的对象（一句话），确认你理解的是同一个命题；
2. 逐条检查以下五类问题，**每个发现都必须给出定位（哪一句/哪一步）**：
   - A 数学内容：假设是否用全、极限/求和/积分交换条件、量词顺序、结论是否过强
   - B 适用范围：引用的定理假设是否覆盖当前情形；边界情形（p=∞、q=∞、s 临界）是否讨论
   - C 引用与文献：文献是否存在、是否被曲解（**不确定就写「需核对原文」，不要猜**）
   - D 记号与一致性：前后记号是否一致、定义是否循环、编号是否错位
   - E 流程风险：这段是否有上下文丢失、是否依赖了未声明的前置结果
3. 对每一步关键推理，回答：**这一步依赖什么？这个依赖成立吗？**
4. 至少尝试一种**换角度**的检验，并说明用了哪种：
   （a）独立重推一遍，与原文对比；
   （b）构造一个可能的反例或极端情形；
   （c）找一个更简单的特例验证；
   （d）对照文献结论句（不是对照摘要或记忆）。
5. 给出结论时必须同时给出**依据类型**：
   推导 / 反例 / 文献 / 计算 / 无法判定。

输出格式：

- 核查对象：
- 使用方式：（a/b/c/d 中哪些）
- 问题清单：
  | # | 类型编号(A1…E4) | 位置 | 描述 | 严重度 |
- 是否存在"推翻了原结论"的情况：是/否/部分
- 结论：[ ] 未发现问题　[ ] 有小问题需修正　[ ] 有严重问题　[ ] 无法判定
- 依据类型：
- 我**无法判定**的部分（诚实列出）：

禁止事项：
- 不要说"看起来是正确的"，除非给出具体验证；
- 不要因为原文很长就默认细节正确；
- 不要修改原文——只报告问题。
```

## 用完之后的动作

1. 把输出整理进「生成-核查记录」Issue 的第 4 节（错误按编号归类）；
2. **人工判定**（第 5 节）必须写依据，不能写"GPT 说对"；
3. 若本次暴露出核查方式本身的缺陷 → 记进 `docs/能力包改进记录.md`。

## 为什么必须换角度

同一个模型重读同一段，往往重复同一个盲区。**核查的价值在于"用另一种方式触碰同一个结论"**：重推、找反例、算特例、查原文——四种里至少一种，否则这次核查等于没做（错误类型 `E2`）。
