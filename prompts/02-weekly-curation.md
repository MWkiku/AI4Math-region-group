# 提示词 02 · 每周精选整理

> 用途：轮值整理人每周把微信群讨论整理成可追踪的内容。群聊无法自动导出，需人工把关键讨论文本贴给 AI。
> 本文件放在团队仓库里，任何 AI（Harness / 豆包 / Codex）或人照此执行，产出格式一致。

```
你是本周的协作整理助手。下面是我们小组本周微信群的讨论记录（可能有口语、重复和无关内容）。
请按「微信交流、定期精选、AI 整理、GitHub 协作与沉淀」的方式，帮我把有价值的内容整理成四类：

1. 问题：值得研究的数学问题或子问题（写清问题陈述，属于哪类问题形状：单点洞察/长链证明/计算/检索综述）；
2. 经验：可复用的方法、踩坑、工具配置或操作技巧；
3. 任务：需要有人去做的事（建议负责人、完成标准、依赖）；
4. 能力包候选：已经跑通、以后可能复用的做法（先用四要素粗描：解决什么问题/怎样操作/样例/限制）。

要求：
- 只整理讨论中确实出现的内容，信息不全的地方标注"待补充"，不要编造；
- 按 templates/weekly-curation.md 的格式输出；
- 对每条任务和能力包候选，提示我是否应在 GitHub 开对应 Issue；
- 明确标出哪些结论还没验证、需要人工判断；
- 保留讨论里有价值的原话（如卡点、关键洞察），并注明大概是谁提出的（不确定就写"待确认"）。

本周讨论记录如下：
<把本周微信群的关键讨论粘贴在这里>
```

## 整理后人工动作
- 相关成员确认 AI 的整理（**AI 的归纳不是事实，只是候选**）；
- 任务 / 卡点 / 能力包候选分别在 GitHub 开 Issue（选对应模板）；
- 纯经验记入仓库 `docs/` 或本周小组周报；
- 周精选文件进 `docs/周精选/`，命名见该目录 README。
