# 协作流程图与单一事实源对照

> 本文件放进团队仓库，作为"内容去哪、谁来做、走什么流程"的一页纸。

## 一、八环节闭环

```
 ①微信群讨论      ②小组精选整理      ③明确问题与任务     ④分工研究
   (交流)        (轮值整理人+AI)     (开 Issue)        (功能分支)
      │                                                          │
      ▼                                                          ▼
 ⑧课程主页展示   ⑦提炼能力包       ⑥改进与汇报        ⑤同伴核查
  (成熟成果/      (四要素+交叉       (周报/汇报)        (PR 评审后
   技能包下载)     试用入库)                              合并)
      │
      └──────────── 新问题回流 ① 微信群，进入下一轮 ───────────┘
```

## 二、每个环节用什么工具、产出什么

| 环节 | 主要工具 / 做法 | 产出 |
|---|---|---|
| ① 日常沟通 | 微信群 | 提问、讨论、分享、报困难、通知 |
| ② 精选整理 | 轮值整理人 + AI，`templates/weekly-curation.md` | 周精选：问题/经验/任务/能力包候选 |
| ③ 项目规划 | GitHub Issues / Projects | 任务、负责人、完成标准、进度 |
| ④ 研究执行 | 各选模型、Harness、Danus、计算/可视化工具 | 分支提交、工具链说明、实验记录 |
| ⑤ 同伴核查 | GitHub 分支、Pull Request | 经过检查/复现的合并 |
| ⑥ 改进汇报 | `templates/小组周报.md`、飞书幻灯片、Overleaf | 周报、汇报 PPT、正式报告 |
| ⑦ 提炼能力包 | 四要素 + `checklist/skill-intake-checklist.md` | 能力包 zip、交叉试用记录 |
| ⑧ 成果展示 | 课程主页 / 技能包库 | 可下载的成熟成果与版本 |

## 三、单一事实源（重要）

| 内容 | 唯一主位置 | 不要做的事 |
|---|---|---|
| 交流过程 | 微信群 | 但正式任务/决定必须再进 GitHub，不只停留在群里 |
| 任务/代码/工作流/实验说明/技能包 | GitHub 仓库 | 不要只存在某个人电脑或群文件 |
| 文献条目、阅读笔记、引用 | Zotero | 不要把文献 PDF 散落多处 |
| 数据、录屏、PPT、大型附件 | 坚果云 | 大文件不要进 git |
| 协作中的数学正文 | Overleaf | 阶段成果链接/归档回 GitHub |
| 成熟成果与下载 | 课程主页 / 技能包库 | 链接到具体可复用版本 |

## 四、AI 与人的分工

| AI 做（整理/辅助/核查/成文） | 人做（决策/判断/责任） |
|---|---|
| 整理每周群聊为四类 | 确定研究问题 |
| 辅助研究、跑计算、查资料 | 选择研究路线 |
| 协助核查、做第二模型复核 | 判断证据是否成立 |
| 整理周报、能力包草稿 | 决定是否收录、公开发布 |

## 五、轮值机制
- 每组每周一名轮值整理人，轮流担任，每周少量时间精选讨论；
- 能力包候选须说清四要素，并由**另一位成员或另一小组**试用可复现后，才决定入库。

## 六、两组最终成果
1. 围绕具体数学问题的**研究进展**；
2. 可在不同项目中复用的 **AI4Math 能力包**。
