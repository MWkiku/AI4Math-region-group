## 五、怎么开始一次协作

1. **有想法**：在微信群说 → 由轮值整理人进周精选；
2. **要动手**：开 Issue（`研究任务` 模板），写清负责人、完成标准、依赖；
3. **做研究**：从 `main` 拉功能分支，分支名 `#编号-关键词`，小步提交；
4. **交结果**：发 Pull Request，填模板（改了什么 / 结论状态 / AI 参与了哪些 / 验证情况）；
5. **过核查**：由**另一位成员**检查、复现或核查，通过才合并；
6. **标状态**：猜想 / 部分证明 / 待核查 / 已完成内部核查——**合并 PR ≠ 定理已证明**。

## 六、每周节奏

- 一名轮值整理人（每周轮换，30–45 分钟）——职责与交接见 [排班表](docs/轮值整理人排班.md)；
- 把群里有价值的讨论交给 AI，用 [整理提示词](prompts/02-weekly-curation.md) + `templates/weekly-curation.md` 整理成**问题 / 经验 / 任务 / 能力包候选**；
- 产出提交进 [`docs/周精选/`](docs/周精选/README.md)；
- 相关成员确认后：任务 → 研究任务 Issue；卡点 → 卡点求助 Issue；可复用方法 → 能力包候选 Issue；纯经验 → `docs/` 或周报；
- 周末用 `checklist/weekly-checklist.md` 过一遍。

## 七、AI 参与与署名

任何由 AI 生成 / 整理的内容，在 PR 模板「AI 参与情况」里写明底座、模型、完成了哪些部分、人工复核了哪些部分。未经验证的结论不写入正式成果。

## 八、本仓说明

本仓库的文件结构由 AI4Math 课程能力包《团队协作与知识沉淀工作流》的 `kit/` 脚手架生成（AI 复制整理，人工确认）。
新增的文件只有 `README.md`（本文件）、`AGENTS.md` 顶部「零、本组协作约定」一节、`.gitignore`；其余模板与清单保持脚手架原样，未改原则。
