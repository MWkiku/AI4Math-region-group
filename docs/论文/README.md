# 论文流水线 · 生成—核查—记录

> 正文由 AI 生成，但**每一块都要有人签字**。这一页说明谁在哪一步做什么。

## 一、主位置（**已定：Overleaf 为准**，2026-10-22）

| 内容 | 位置 | 规则 |
|---|---|---|
| **论文正文** | **Overleaf（唯一主位置）** | 以 Overleaf 上的版本为唯一准；AI 生成的片段由人粘进去 |
| 被核查过的片段快照 | 仓库 `docs/论文/快照/T__-<关键词>.md` | **只是快照，不是主位置**；必须写「抓取时间 + 对应 Overleaf 位置」，用于 Issue 可追溯 |
| 定理/片段登记、错误统计、核查记录 | 仓库 `docs/论文/` 与 Issue | 记录层，不进正文 |
| 图表数据、录屏、大附件 | 坚果云 | 大文件不进 git |

**两个必须遵守的操作细节**（Overleaf 为准带来的必然要求）：

1. **每次生成前，先把 Overleaf 上的当前版本贴给 AI**。否则 AI 基于旧稿生成，你会得到"看起来接得上、实际矛盾"的内容（错误类型 `E1`）。
2. **粘贴回 Overleaf 后，把那一版快照存进仓库**，并在登记表里记下 Overleaf 位置。**没有快照的核查记录，三周后没人能复核。**

> 之前这里写的是「仓库 `paper/` 为准」，已按 2026-10-22 决定改为 Overleaf 为准。

## 三、五步流水线

```
①切片 → ②生成 → ③核查 → ④判定 → ⑤记录与汇报 → （回流改进能力包）
```

| 步 | 做什么 | 谁 | 产出 |
|---|---|---|---|
| ① 切片 | 把论文拆成可核查单元：定理 `T1…`、证明步骤、段落 `P1…` | 章节负责人 | 编号登记进 `定理登记表.md` |
| ② 生成 | DeepSeek 按提示词生成该切片 | 章节负责人 | 内容 + prompt 摘要 + 模型版本 + 原始输出位置 |
| ③ 核查 | **非生成方**（GPT + 人）逐项核查 | 朱晨峰 / 另一成员 | 错误清单（按类型分类） |
| ④ 判定 | 人给结论与状态 | 判定人（不得是生成者） | 采纳 / 修正后采纳 / 驳回 / 存疑待查 |
| ⑤ 记录与汇报 | **仅对「查出错误」的切片**开「生成-核查记录」Issue；未出错的切片只登记不单开 | 轮值主讲人 | Issue（仅错误项）+ 周汇报 + 能力包改进候选 |

> **粒度规则（2026-10-22 决定）**：目前**只对发现错误的切片开 Issue**，未出错的切片只进 `定理登记表.md`（一行成本极低），避免 Issue 泛滥。以后需要更细的追溯时再逐步收紧。
> 代价要认清：**「这周没查出错」的证据只存在于登记表里**——所以登记表不能省，否则无法回答"到底是没查，还是查了没问题"。

## 四、硬规则（四条，违反即为流程失效）

1. **双模型一致 ≠ 正确**：还须一项不依赖模型的依据（推导、文献、计算、反例搜索），否则只能标「待核查」。
2. **核查方 ≠ 生成方**：模型不重合（DeepSeek 生成 / GPT 核查），人也不重合（谁生成谁不签字）。
3. **没有切片编号的内容不入正文**：Issue 里说不清"错在哪一段"，就等于没记录下来。
4. **未标状态的结论不进正式稿**：猜想 / 部分证明 / 待核查 / 已完成内部核查，四档必选其一。

## 五、每周怎么跑

- 每位章节负责人把**本周新生成或修改**的切片过一遍 ②③④；
- 轮值主讲人汇总成一份 `templates/周汇报.md`，课上 5 分钟讲；
- 课后再把汇报里的结论落成 Issue（没进 Issue 的不算发生）；
- 暴露的流程问题 → `docs/能力包改进记录.md` → 评估是否更新到下一个版本。

## 六、隐私与合规

- 不要把**含个人信息、未公开他人成果、受版权限制的全文**贴进模型；
- 引用他人结果时，核查项里必须有一项是"核对原文，而不是核对我对原文的记忆"。
