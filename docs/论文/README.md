# 论文流水线 · 生成—核查—记录

> 正文由 AI 生成，但**每一块都要有人签字**。这一页说明谁在哪一步做什么。

## 一、主位置（**待组长确认**）

| 内容 | 位置 | 理由 |
|---|---|---|
| 章节源文件（`.tex` 或 `.md`） | 仓库 `paper/` | AI 可直接读写；每次改动进 git，可追溯到哪个 Issue |
| 编译与人工润色 | Overleaf | 人写人改更方便；**是镜像，不是唯一存档** |
| 图表数据、录屏、大附件 | 坚果云 | 大文件不进 git |

> 现在"正文放 Overleaf"和"AI 在仓库里生成"是**两个主位置**，必须选一个当准。若不确定，先用仓库 `paper/` 为准、Overleaf 当工作副本——否则一定会出现"仓库里是旧版、Overleaf 里是新版"。

## 二、五步流水线

```
①切片 → ②生成 → ③核查 → ④判定 → ⑤记录与汇报 → （回流改进能力包）
```

| 步 | 做什么 | 谁 | 产出 |
|---|---|---|---|
| ① 切片 | 把论文拆成可核查单元：定理 `T1…`、证明步骤、段落 `P1…` | 章节负责人 | 编号登记进 `定理登记表.md` |
| ② 生成 | DeepSeek 按提示词生成该切片 | 章节负责人 | 内容 + prompt 摘要 + 模型版本 + 原始输出位置 |
| ③ 核查 | **非生成方**（GPT + 人）逐项核查 | 朱晨峰 / 另一成员 | 错误清单（按类型分类） |
| ④ 判定 | 人给结论与状态 | 判定人（不得是生成者） | 采纳 / 修正后采纳 / 驳回 / 存疑待查 |
| ⑤ 记录与汇报 | 开「生成-核查记录」Issue；轮值主讲人课上汇报 | 轮值主讲人 | Issue + 周汇报 + 能力包改进候选 |

## 三、硬规则（四条，违反即为流程失效）

1. **双模型一致 ≠ 正确**：还须一项不依赖模型的依据（推导、文献、计算、反例搜索），否则只能标「待核查」。
2. **核查方 ≠ 生成方**：模型不重合（DeepSeek 生成 / GPT 核查），人也不重合（谁生成谁不签字）。
3. **没有切片编号的内容不入正文**：Issue 里说不清"错在哪一段"，就等于没记录下来。
4. **未标状态的结论不进正式稿**：猜想 / 部分证明 / 待核查 / 已完成内部核查，四档必选其一。

## 四、每周怎么跑

- 每位章节负责人把**本周新生成或修改**的切片过一遍 ②③④；
- 轮值主讲人汇总成一份 `templates/周汇报.md`，课上 5 分钟讲；
- 课后再把汇报里的结论落成 Issue（没进 Issue 的不算发生）；
- 暴露的流程问题 → `docs/能力包改进记录.md` → 评估是否更新到下一个版本。

## 五、隐私与合规

- 不要把**含个人信息、未公开他人成果、受版权限制的全文**贴进模型；
- 引用他人结果时，核查项里必须有一项是"核对原文，而不是核对我对原文的记忆"。
