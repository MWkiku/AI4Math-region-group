# 轮值整理人 · 排班与职责

> 每周一名，轮换担任。核心只有一句：**把这一周群里长出来的东西，变成 GitHub 上追得到的东西。**

## 一、职责（30–45 分钟/周）

| # | 动作 | 产出 |
|---|---|---|
| 1 | 从微信群挑出本周**有价值**的讨论，复制成文本（不用全量） | 一段原始文本 |
| 2 | 交给 AI，用 `prompts/02-weekly-curation.md` 整理成四类 | 《周精选》草稿 |
| 3 | 找相关成员确认（谁提的问题、谁领的任务） | 确认记录 |
| 4 | 按需开 Issue：任务 / 卡点 / 能力包候选 | 若干 Issue |
| 5 | 把《周精选》提交进 `docs/周精选/` | 一个提交 |
| 6 | 用 `checklist/weekly-checklist.md` 过一遍，交接给下一位 | 勾完的清单 |

**不做的事**：不替别人定研究结论、不判断数学对错、不把 AI 的归纳当成事实——只做**搬运和归类**，判断留给当事人。

## 三、交接（每周结束时，30 秒）

下一位接手前，上一位只需在群里交代三句：

1. 本周整理了哪几条（贴 Issue 编号或周精选文件名）；
2. 哪几条**还没确认**、卡在谁那里；
3. 下周需要重点盯什么。

## 四、常见坑

- **攒着不做**：两周的讨论堆在一起，细节已经忘了。宁可每周只整理 2 条。
- **只整理问题、不整理失败**：失败的路线、踩过的坑同样要写进周精选（`研究路线笔记.md` 里也留档）。
- **AI 说什么就写什么**：AI 整理出的「问题陈述」可能把你们的原意拧歪，必须让提出人看一眼。
- **只开 Issue 不写人**：Issue 没有负责人和完成标准，等于没有。

## 五、第一次怎么起步

第一次不用等「攒够一周」。本周群里只要出现了**一个**具体的问题或一件要有人做的事，就开始第一份周精选——从一条开始，比等一份完美的容易。
