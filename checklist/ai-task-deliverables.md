# AI 研究任务交付标准

> AI 能快速生成多条路线，合作中的困难转为：哪些值得继续、哪些已经检查、哪些只是重复或错误。
> 交给 AI（或同学）的每个研究任务，交付时**逐项核对**以下六项；缺项就标注"待补充"，不能含糊带过。

## 交付前核对（六项，缺一即未完成）

- [ ] **1. 精确的问题和假设**：要解决什么、在什么假设/条件下，写清楚。
- [ ] **2. 本次尝试的方法**：用了什么思路、路线、工具，而非只给结论。
- [ ] **3. 结论及证据**：得到什么结论，依据是什么（证明 / 文献 / 计算 / 图）。
- [ ] **4. 尚未核实的引用或步骤**：哪些引用、哪一步还没确认，明确列出。
- [ ] **5. 失败原因与下一步建议**：失败在哪、排除了什么、建议接着做什么。
- [ ] **6. 模型 / 工具 / 运行信息**：底座、模型、工作流、版本，便于复现。

## 记录形态要求

- AI 的**长对话**只作为附件或链接保存；
- **主记录**必须是人能直接阅读、核查并接着工作的研究笔记（用 `研究路线笔记.md`）。

## 判定提示

- 只有"模型说可以"而没有证据 → 状态标「待核查」，不进入正式结论；
- 引用无法定位、条件不匹配 → 列为「尚未核实」，不能当作依据；
- 只对当前问题有效、不具一般性 → 先留在问题空间，不急于提炼成能力包。
