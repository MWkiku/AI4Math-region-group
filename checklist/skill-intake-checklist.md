# 能力包收录验收清单

> 一个能力包候选在收入技能包库、上课程主页之前，逐项核对。缺一不可。

## 一、四要素是否说清
- [ ] **解决什么问题**：原来卡在哪、不解决会怎样
- [ ] **怎样操作**：步骤、依赖、底座/模型/工具版本清楚，别人照着能做
- [ ] **用过什么样例**：至少一个真实跑通的输入输出样例（脱敏）
- [ ] **有什么限制**：适用边界、易错点、前置条件

## 二、结构是否完整
- [ ] 解压后是一个根目录 `skill-<英文短名>/`
- [ ] 有 `SKILL.md`（AI 主文档）和 `manifest.json`（机器元数据）
- [ ] 有 `CHANGELOG.md`，版本号符合 `v主.次`
- [ ] 有 `prompts/`、`examples/`（至少一组真实样例）
- [ ] 依赖、输入、输出明确，结果可判定

## 三、是否可复现（决定成熟度）
- [ ] 本人确实跑通过（不是设想）
- [ ] **另一位成员或另一个小组按手册实际试用过**
- [ ] 试用结果能复现；不能复现的已记录原因
- [ ] 成熟度与实际一致：未被复现最高 L1；复现一次 L2；多组验证 L3

## 四、安全合规（红线）
- [ ] 不含任何 API Key、密码、私有密钥
- [ ] 示例中的真实姓名、学号、账号、数据、路径已脱敏
- [ ] 不含未公开的他人成果
- [ ] 不含受版权限制的文献全文

## 五、可复用性
- [ ] 解决的是一类问题，而不是一次性偶然成功
- [ ] 触发场景明确（什么时候该用它）
- [ ] 工具链可替换处已说明，核心原则不依赖特定工具

## 六、署名与归档
- [ ] 提报人与 AI 参与情况已如实标注
- [ ] 已按命名规范打包：`AI4Math能力包_<类别>_<名称>_v<版本>.zip`
- [ ] 已在技能包库登记，并在课程主页展示
- [ ] 团队仓库里留有对应的交叉试用记录
